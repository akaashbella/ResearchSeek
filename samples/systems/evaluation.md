# Evaluation protocol

A retrieval experiment needs a fixed corpus, a fixed set of queries, and relevance labels assigned before interpreting the result. Exact terminology and paraphrases exercise different behavior, so both belong in the evaluation set. For example, a query about preventing overfitting might be relevant to a note about regularization even when the note never uses the query's wording. That example is a hypothesis for a labeled test rather than evidence of model quality. The keyword baseline should use the same passages as the semantic method. Otherwise, differences in passage boundaries could explain a change in recall. Record the model revision, tokenizer settings, source hashes, chunking parameters, and package versions alongside the results. Keep query encoding time separate from the native vector scan, and measure the complete command as well. A fast kernel may contribute little to total latency if loading vectors or starting the interpreter dominates. Warmup runs can initialize caches but should not be included in the measured sample. Report individual timing observations and percentile summaries, including slower runs. An unchanged indexing run should be evaluated separately from a first run because it hashes files without generating new passage embeddings. Modified-file experiments should specify which files changed and how many chunks were replaced. These controls make the experiment repeatable and help explain negative findings without inventing a performance improvement.
